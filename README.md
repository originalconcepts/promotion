# Promotion Engine — תוסף מבצעים ל-WooCommerce

מנוע מבצעים עצמאי ל-WooCommerce, בנוי כך שיתחבר בהמשך ל-Giorgio דרך API.
שם התצוגה הוא placeholder — ניתן לשנותו במקום אחד: `PROMENG_DISPLAY_NAME` בקובץ הראשי.

---

## עיקרון ארכיטקטוני

התוסף **הוא המנוע**. הוא מחשב מחירים ב-PHP ומחיל אותם על הסל של WooCommerce.
הוא **לא** תלוי ב-Giorgio בזמן ריצה — הקופה ממשיכה לעבוד גם אם Giorgio לא זמין.

ללקוחות Giorgio (שלב 3): הגדרות מבצע ייכנסו מ-Giorgio אל הטבלאות כאן
(`source = 'giorgio'`, לקריאה בלבד ב-WP), ואירועי מימוש ידווחו חזרה למעלה
כדי שהדשבורד המאוחד ב-Giorgio יכלול את פעילות האתר. כל הקרסים (hooks)
לכך כבר במקום: עמודות `source` / `external_id` / `reported_to_giorgio`,
ה-cron `promeng_giorgio_sync`, ו-action ה-`promeng_register_types`.

---

## מה עובד עכשיו (v0.1)

מבצע מסוג **% / ₪ הנחה** — מקצה לקצה:

- יצירה/עריכה/רשימה במסך ניהול ("מבצעים" תחת תפריט OC Pluginz המשותף)
- מיקוד: כל המוצרים / מוצרים ספציפיים / קטגוריות ספציפיות / כל הסל
- מוצרים מוחרגים (ל"כל המוצרים" ו"קטגוריות")
- תנאי קנייה: לפחות X פריטים / מעל X ש"ח
- אחוז או סכום קבוע
- תזמון: טווח תאריכים + ימי שבוע
- הגבלה ללקוח (נאכפת מול טבלת המימושים)
- תווית "במבצע" / שם המבצע בקטלוג (כשמסומן)
- הודעת חיסכון בסיכום הסל
- טוגל סטטוס, שכפול, מחיקה ברשימה
- רישום מימושים על הזמנה (לבסיס הדשבורד והדיווח ל-Giorgio)

החלה בסל: הנחות פר-שורה דרך `set_price`, הנחת כל-סל דרך fee שלילי —
שני ה-hooks הסטנדרטיים של WooCommerce.

## מה עדיין לא (שלבים הבאים)

**שלב 2 — סוגי מבצע נוספים + קופונים**
- קנה X שלם Y, קנה X קבל Y (ה-interface וה-engine כבר מוכנים לקלוט אותם)
- הזנת קוד קופון בקופה ואימותו (כרגע רק מבצעים אוטומטיים מוחלים)
- הקצאת "הגבל ל X פריטים" לפי החוק הישראלי (כרגע ההנחה חלה על כל היחידות)

**שלב 3 — אינטגרציית Giorgio**
- סנכרון הגדרות Giorgio → תוסף
- דיווח מימושים תוסף → Giorgio
- חסימת UI היצירה כשמחובר ל-Giorgio (הלוגיקה ל-read-only כבר קיימת)

**שלב 4 — ליטוש**
- כל וריאנטי הודעות העידוד/חיסכון מהאפיון (לפני הגעה לכמות, מתנה אוטומטית, פופאפ בחירה)
- מסך הגדרות (תוספת מעל כמות, הזמנות טלפוניות, מבצע על מוזלים)
- חוקיות ערימה (stacking) חוצה-מבצעים — ההחלטה העקרונית שדיברנו עליה
- i18n מלא, בדיקות אוטומטיות

---

## התקנה

1. דחוס את התיקייה `promotion-engine` ל-zip (או השתמש ב-zip המצורף).
2. WP Admin → תוספים → העלאת תוסף → בחר את ה-zip → הפעל.
3. דורש WooCommerce פעיל.
4. הכניסה "מבצעים" תופיע תחת תפריט OC Pluginz בצד; "הגדרות" ו"סנכרון Giorgio" הן לשוניות מעל המסך.

> הערה: נבדק לתקינות תחביר (PHP 8.3). בדיקת אינטגרציה חיה מול WooCommerce
> צריכה להתבצע על סביבת בדיקה לפני עלייה לפרודקשן.

## רישיון ומצב מוגבל (0.12.0)

הרישיון של OC Pluginz (לשונית "חשבון OC Pluginz" בהגדרות) קובע אם המבצעים **מוחלים** בחנות:

- **מצב מלא** — רישיון פעיל, לכל החיים, מסתיים בקרוב או בימי החסד (7 ימים); מפתח שההאב עדיין לא ענה עליו; `OC_PLUGINZ_AGENCY`.
- **מצב מוגבל** — אין מפתח (מהיום הראשון), מפתח מושהה/שנדחה, או תפוגה שההאב אישר אחרי ימי החסד. ההאב לא נגיש? המצב האחרון נשאר — outage לא מגביל אף פעם.
- **אתר שמחובר ל‑Giorgio** (כתובת API ומפתח בלשונית "סנכרון Giorgio", או מבצעים שהגיעו מ‑Giorgio) — תמיד מלא, גם בלי מפתח וגם כשהמפתח מושהה.

במצב מוגבל הלקוחות רואים מחירים מלאים: אין הנחות שורה/סל (גם בקופת blocks), אין שורות חיסכון והודעות, אין קודי קופון של התוסף, אין תוויות ומחירי מבצע בקטלוג, מתנות אוטומטיות לא מתווספות. **כלום לא נמחק**: כל המבצעים, העריכה, הסטטיסטיקה, ה‑meta של ההזמנות, ההגדרות, סנכרון Giorgio וה‑REST שלו ממשיכים כרגיל; שורה פעילה ברשימה מסומנת "לא פעיל — רישיון". במעבר למצב מוגבל: הודעה אדומה בכל מסכי הניהול (ניתנת לסגירה ליום) ומייל אחד ל‑admin_email.

בדיקות: `php tests/logic-test.php` (ללא WordPress, רץ ב‑CI), `php tests/integration/licence-smoke.php` על אתר בדיקה עם WooCommerce.
